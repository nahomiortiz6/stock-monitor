
# Stock Alert System with AI

An automated stock monitoring pipeline that tracks a personal watchlist, detects statistically significant price movements, and sends AI-enriched alert emails — running entirely on GitHub Actions for less than $3/month.

This project was built as a portfolio piece demonstrating practical LLM integration in a production data pipeline. It is designed to **inform**, not automate trading — all purchase decisions are made manually by the user.

---

## What it does

Every 30 minutes during US market hours, the system:

1. Pulls 2 years of daily price history for ~26 tickers (ETFs and individual equities).
2. Computes technical indicators (ATR, RSI) and compares current price action against volatility-adjusted thresholds.
3. Scores each triggered signal by **severity** and applies a cooldown/escalation policy to avoid alert spam.
4. Sends a single consolidated email per run, with each alert enriched by a plain-language interpretation generated by Claude Haiku.
5. Persists run state (last alert times, monthly LLM call counter, etc.) to a dedicated Git branch, so the pipeline is fully stateless between runs and requires no external database.

All user-facing content (email subject, body, LLM interpretation) is written in **Spanish**, since that's the target audience for the alerts.

---

## Why it exists

Manually checking 26 tickers for meaningful moves — as opposed to routine daily noise — doesn't scale. This system encodes that judgment call (what counts as "significant," accounting for each asset's own volatility) into a deterministic rule set, and uses an LLM only for the last step: translating a triggered signal into a short, readable explanation a non-technical reader can act on.

## Alert logic

The core question the engine answers is: *"Is this move unusual for this specific asset, right now?"* — not an absolute percentage cutoff.

- **ATR (Average True Range, 14-period, Wilder smoothing):** normalized as `atr_pct = ATR / price` so volatility is comparable across assets trading at very different price levels. A 1-day move is flagged when it exceeds `atr_pct × 1.5`; a 5-day move when it exceeds `atr_pct × 2.5` (an approximation of the √5 random-walk scaling factor). Higher recent volatility raises the bar for what counts as significant — this is an intentional desensitization during turbulent periods, not a bug.
- **RSI (14-period):** normalized as `(distance_from_boundary / 30) + 1`, so a value of exactly 1.0 means the asset is precisely at the overbought/oversold trigger.
- **Severity:** `severity = actual_move / threshold` for each metric; the maximum severity across all triggered metrics in a run is what's reported.
- **Cooldown:** once an alert fires for an asset, repeat alerts for the same event are suppressed for 24 hours — *unless* severity increases by at least 1.3x, which is treated as a genuinely worsening event and re-alerted. A recovery followed by a re-breach within the same window does not count as a new event.
- **52-week range and Golden/Death Cross** are included in the email as contextual information only; they don't factor into the severity score.

```
         │
         ▼
```

## Tech stack

| Component | Choice | Notes |
|---|---|---|
| Language | Python 3.12 | |
| Market data | [yfinance](https://github.com/ranaroussi/yfinance) | 2-year daily history, `auto_adjust=True` |
| Indicators | [pandas-ta-classic](https://pypi.org/project/pandas-ta-classic/) 0.6.52 | Avoids silently incorrect RSI from a non-Wilder smoothing implementation |
| Market calendar | [exchange_calendars](https://github.com/gerrymanoim/exchange_calendars) | NYSE holidays and session times; also gates runs in real time |
| LLM | Claude Haiku 4.5 via Anthropic API | Chosen for cost; usage capped via prepaid credits (no auto-reload) + a monthly call counter in state |
| Email | Gmail SMTP (app password) | `MIMEText`, UTF-8 |
| Orchestration | GitHub Actions | `cancel-in-progress: true`, `timeout-minutes: 8` |
| State | JSON on an orphan `state` git branch | No external database; kept out of `master` history via `git worktree` |

## Cost

Designed to run under **$3/month**:
- GitHub Actions: free tier covers this schedule comfortably on a public repo.
- Anthropic API: Claude Haiku 4.5 with usage tracked monthly in state.json; cost ceiling enforced by prepaid credits with auto-reload disabled.
- No paid database, server, or hosting — state lives in the repo itself.

## Setup

> Requires a GitHub account, a Gmail account with an [app password](https://support.google.com/accounts/answer/185833) enabled, and an Anthropic API key.

1. **Clone the repository**
   ```bash
   git clone https://github.com/<your-username>/<repo-name>.git
   cd <repo-name>
   ```

2. **Create the state branch** (only needed once, before the first run)
   ```bash
   git checkout --orphan state
   git rm -rf .
   echo '{}' > state.json
   git add state.json
   git commit -m "Initialize state branch"
   git push origin state
   git checkout master
   ```

3. **Set repository secrets** under Settings → Secrets and variables → Actions:
   | Secret | Description |
   |---|---|
   | `ANTHROPIC_API_KEY` | Anthropic API key |
   | `GMAIL_ADDRESS` | Sender Gmail address |
   | `GMAIL_APP_PASSWORD` | Gmail app password |
   | `ALERT_RECIPIENT_EMAIL` | Where alerts are sent |

4. **Edit the watchlist** in `config/watchlist.yaml` to your own tickers.

5. **Enable the workflow** — it runs automatically on the defined cron schedule. To trigger a manual test run:
   ```bash
   python3 -m src.main
   ```
   Note: always run as a module (`python3 -m src.main`), not `python3 src/main.py` — the package uses relative imports that require the module context.

6. A monthly `keepalive.yml` workflow pings the repo to prevent GitHub's automatic disabling of scheduled workflows after 60 days of repo inactivity.

```
  llm_client.py             # Claude API calls
  email_sender.py           # SMTP email composition and sending

  monitor.yml               # main scheduled pipeline
  keepalive.yml              # prevents workflow auto-disable
```
